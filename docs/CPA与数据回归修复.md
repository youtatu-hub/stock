更新代码后重启 Python 服务；Docker 使用 `docker compose up -d --build`，随后刷新浏览器。
`/api/health` 应包含 `flow_api_version: 7`、`premium_api_version: 4` 和 `ai_api_version: 3`。

`premium_api_version: 4` 表示免费来源参考展示已更新，不代表实时 IOPV 已恢复。页面直接显示来源最近收到的 IOPV 参考值、来源参考折溢价、对应快照市价、行情时间和本站获取时间；IOPV 计算时间未提供时保持为空。参考折溢价仅取来源返回值，来源缺失时不自行补算。行情过期标为旧报价，刷新失败保留上次参考并明确报错。该区块不触发实时提醒，也不作为实时 IOPV 传入 AI；无需安装 RQData。

## CPA 使用

右侧所有品种均显示「CPA · AI 智能解读」，包括五只美股 ETF 和场外基金。
页面只提供模型选择框和「刷新模型」按钮；初次打开自动读取模型并生成解读。
切换品种、日周周期或模型时自动重新解读，快速切换合并为一次请求。普通行情金额刷新不重复调用模型；资金流可用性、来源或数据日期变化时重新解读。
「刷新模型」会重新读取列表，并更新当前品种的解读，也可用于失败后重试。

- 使用 `GET /v1/models` 获取模型，`POST /v1/chat/completions` 生成解读，认证为 `Authorization: Bearer <key>`。
- URL 和 Key 固定存放在后端 `data/cpa_private.json`，字段为 `base_url`、`api_key`、`model`（默认模型可留空）。配置只在后端读取，修改后需重启服务。
- 该私有文件已加入 Git 和 Docker 构建排除；Docker Compose 以只读文件挂载。部署到另一台机器时需单独复制该文件，不能仅拉取 Git 代码。
- 浏览器只记住模型名称，并清除上一版本保存在浏览器的连接配置；接口不返回 URL/Key，也不接受前端传入的连接配置。旧 `/api/ai/config` 已移除。
- 模型解读自动发送当前品种的行情与分析数据；取消或切换后，迟到回复不会覆盖新页面。
- CPA 解读与本地规则结论分开显示。模型失败会明确显示失败；不会伪造分析成功。

## 16、19、23 的复查口径

- **16**：检查 `missing_ranges`、`missing_count` 和逐分钟的 `available`。腾讯09:31–10:29的59条不可核验记录应为缺口；后续有效累计值保留。首小时变成非零值不再作为验收标准。累计平台本身不判错，开盘累计流出大于收盘也不判错。
- **19（未完成）**：当前来源未提供IOPV计算时间，接口的当前IOPV和实时折溢价保持为空。页面显示「来源 IOPV 参考／估值时效未核验」，`reported_reference` 中的参考值与来源折溢价默认展开，整个对象仍从AI输入中删除。来源参考模式下提醒输入框禁用。以后接入真实来源时，先运行独立探针 `tools/probe_rqdata_iopv.py`，按[IOPV真实源核验清单](IOPV真实源核验清单.md)核验五只ETF后再接入；免费参考展示不依赖这个商业数据源。探针默认15分钟门槛不改变业务现有校验。模型估算只能另记功能，不能据此关闭第19项。
- **23**：实时模式下，AI请求携带 `flow_snapshot: {id, status}`。服务保存5分钟的轻量快照，模型生成期间的新轮询不能替换所引用的版本；过期或错品种引用明确失败。响应返回本次使用的 `fund_flow`，AI卡片标明截至时间及来源。有效累计、分钟缺口和日级未请求分别表达。日级展示模式不等待实时面板渲染，由后端同一实时服务提供本次分析快照。
