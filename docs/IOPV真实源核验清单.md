# IOPV 真实来源核验清单

核验范围：513500、513300、159501、159941、513100。第 19 项仍未完成。

目标是取得可以用于当前折溢价计算的 IOPV，并核验它的估值依据和时效。交易所今天发布过一个数值、接口请求成功、字段名包含“实时”，均不能单独满足验收要求。模型估算另记功能，不计入第 19 项。

本文用于后续真实 IOPV 来源接入：先运行独立探针，取得真实样本并核验通过后，才恢复实时估值与提醒。

当前另行实现了免费来源参考展示（`premium_api_version: 4`）：腾讯优先，来源最近收到的 IOPV 与来源折溢价默认可见，计算时间未知时保持为空。参考对象不进入实时提醒或 AI 估值，无需 RQData 环境；这项展示改动不表示本文核验已通过。

## 当前状态与前置条件

- 当前腾讯、东方财富解析结果没有 IOPV 独立估值时间，`iopv_time` 为空。现有不可用状态、提醒限制和 AI 输入隔离继续保留。
- AKShare 的 `fund_etf_spot_em` 仍取自东方财富；行情行的“更新时间”不能直接填入 `iopv_time`。
- RQData 文档列出了 tick 的 `iopv`、`prev_iopv` 和交易所时间戳。它是候选来源，字段存在不等于五只 ETF 都有值，也不等于时间戳就是 IOPV 估值时间。
- 2026-11-24 在本项目使用的 stock Python 环境中，未发现 `rqdatac`、`xtquant`、`WindPy`、`iFinDPy` SDK 或相关环境配置，也未发现名称匹配的运行中行情终端。这不能证明其他机器或环境没有权限；实际行情核验尚未执行。
- 开始采集前确认已有账号的五只 ETF 覆盖、历史 tick 与实时数据权限、标称延迟、调用限制、使用授权及费用。试用或历史权限不能代替实时权限；新增费用需单独确认。

## 独立探针的运行方法

脚本位于 `tools/probe_rqdata_iopv.py`，不导入业务模块、不写行情文件、不改缓存或功能状态。使用已有授权的 RQData Python 环境；SDK 未安装时先按供应商支持的 Python 版本安装 `rqdatac`。授权使用 SDK 原生许可配置或环境变量 `RQDATAC_CONF` / `RQDATAC2_CONF`，不通过命令行参数传入凭据，脚本不输出其内容。

```powershell
# 无网络预检查；退出码 2 表示尚未执行真实核验。
python tools/probe_rqdata_iopv.py --check-env

# 盘中采样一次，并拉取上一个交易日的历史 tick。
python tools/probe_rqdata_iopv.py --halt-calendar "$env:TEMP/rqdata-halts.json"

# 可选：指定今天之前、最近 60 天内的完整交易日，或收紧探针门槛。
python tools/probe_rqdata_iopv.py --date 2026-11-23 --max-age-seconds 120
```

`current_snapshot` 一次请求五只，记录请求开始时间、接收时间、交易所 tick 时间、IOPV、价格和 `prev_iopv`。`get_price` 逐只请求 `frequency='tick'`、`fields=['last', 'iopv']`、`skip_suspended=True`；`datetime` 从返回的 DataFrame 索引读取。关闭默认停牌补值，不拼接或前向填充。历史日期通过 RQData 交易日历确定，默认使用今天之前最近一个交易日，不把当日尚未完成的数据作为全日样本。

快照只在当日连续交易时段、时间不在未来、未超时且不在停牌期间时才有效。午休、盘前、收盘后或非交易日运行，实时验收为 `not_ready`，历史统计仍可查看。阈值按本轮要求默认 **900 秒（15 分钟）**，允许收紧、不允许继续放宽；报告保留实际延迟，15 分钟筛选通过不能单独证明拥有无延迟的实时权限。该参数只影响探针，业务现有 120 秒限制保持原样。

历史统计包括有效/无效条数、不同值数、变动次数、首末变动时间、最小/最大值、变动幅度及交易时段内最大覆盖缺口。午休和已核实的停牌区间不计为覆盖缺口。`prev_iopv` 与前一交易日末值交叉比较；缺失、不一致或指定历史日并非前一交易日时，保留为待复核，不用它补当前值。

**停复牌证据需要单独提供。** 官方快照文档对 `trading_phase_code` 只明确支持深交所股票，不能假定它覆盖这五只 ETF。探针会拒绝 `H`/`P` 标记，并读取已核实的停牌日历；日历需覆盖历史日和本次采样日，逐只列出区间。空数组表示已核实该品种当日无停牌；缺日期、缺证据不能当成无停牌。以下仅为合成格式示例，不是实际停牌事实：

```json
{
  "2026-01-05": {
    "source": "填写已核实的交易所公告链接或供应商记录说明",
    "symbols": {
      "513300.XSHG": [["09:30", "10:30"]],
      "513500.XSHG": [],
      "513100.XSHG": [],
      "159501.XSHE": [],
      "159941.XSHE": []
    }
  }
}
```

停牌区间按 `[开始时间, 复牌时间)` 处理；复牌后仍停留在停牌前的快照也不能通过，即使其年龄不足 15 分钟。未经停牌核验的快照不会标为 `usable_sample`。

| 探针状态 | 退出码 | 含义 |
| --- | --- | --- |
| `probe_pass` | 0 | 五只均有有效值、全日数据覆盖且存在盘中变化、快照时效满足门槛，停牌记录及前值交叉检查通过；后续仍须核实估值口径、时间语义和授权。 |
| `probe_fail` | 1 | 已具备盘中和停牌核验条件，但本次数据未通过筛选；结合逐只 `checks` 判断原因，不自动切换业务或估算功能。 |
| `needs_review` | 2 | 停牌证据或前值交叉核验尚未完成。 |
| `not_ready` | 2 | 缺少 SDK、仅检查环境，或本次不在正常交易时段。不能据此判定来源失败。 |
| `error` | 1 | 配置、授权、网络、接口或响应校验错误，报告失败阶段和异常类型，不输出可能含凭据的 SDK 异常文本。 |

所有报告均保持 `item_19_complete: false`。探针不把交易所 tick 时间直接写进业务 `iopv_time`，也不会从腾讯、东财取值补缺。准备条件不足时停在核验阶段，不自动实现估算功能。

## 通过与不通过标准

每只 ETF 独立填写结果。证据缺失标为“待核验”，不能算通过；已证实数据不满足要求则标为“不通过”。

| 核验项 | 通过条件 | 不通过或待核验情形 |
| --- | --- | --- |
| 品种与字段 | 代码、市场、币种一致；实时权限下可取得有限且大于零的 `iopv`，同时具有比较用价格。 | 缺值、零占位、错品种、字段其实是已披露净值，或仅有历史权限。`prev_iopv` 不能补当前值。 |
| 时间戳含义 | 提供可核验的估值时间及其定义；如候选只有 tick 时间，必须另取得来源对 IOPV 与该时间的关系、更新方式和陈旧值处理的说明，证明时间确实对应本次估值。 | 只有交易所报价时间、消息发送时间、接口刷新时间或本机获取时间。未经核验不得映射为 `iopv_time`。 |
| 估值依据 | 查明五只 ETF 各自的计算规则，以及成分股价格、汇率、现金等输入的取值时点，证实其满足当前估值要求。 | 仅将隔夜数值随今日报价重复发布，不能证明当前估值依据；只证明“今日发布”而未证明估值有效。 |
| 全日行为 | 取得一个完整交易日的 tick，核对缺值、变化时点、连续不变区间和来源更新规则；按本轮探针要求，五只都要存在盘中变化且覆盖完整交易时段。 | 有无法解释的中断、回退或跳变，或缺少数据导致无法核验。全天不变不通过本次数值筛选，但不能单凭它断言官方数据陈旧；变化也不是估值有效的充分条件。 |
| 实际时效 | 盘中采样有独立接收时间；本轮探针按 `0 <= tick_age <= 900秒` 筛选，并记录实际延迟。业务接入前另行确认时间语义及延时权限；现有业务校验仍为 120 秒。 | 陈旧值、未来时间、未知时间或只有历史数据而没有盘中接收记录。即使门槛内仍须核实是否来自延时权限。 |
| 端到端行为 | 接入后页面、接口、提醒和 AI 使用同一有效快照；缺失、超时、未来时间、刷新失败时均停止当前折溢价和提醒。 | HTTP 200 或单元测试通过，但没有真实源核验；页面显示有效而 AI 或提醒仍引用另一份或过期数据。 |
| 部署与授权 | 实际部署环境可访问，权限、调用频率、延迟和费用适合持续运行。 | 仅本机可用、服务器不可达，或授权及成本未确认。 |

“数值变化”与“估值有效”必须分开判断：美股闭市、价格精度或计算规则可能使官方 IOPV 在盘中保持不变；不变本身不能证明陈旧，变化本身也不能证明实时。即使确认是有效发布的官方 IOPV，如果它仍不满足本项目对当前估值的要求，第 19 项也不能据此关闭。

## 最小核验步骤

1. 确认来源权限及字段说明，选取一个完整的中国交易日，记录对应美股是否交易、相关收盘日期及节假日状态。五只 ETF 使用同一天，代码映射按来源文档核对。
2. 拉取该日原始 tick 的品种、时间、价格、`iopv`、`prev_iopv` 及来源实际提供的估值时间字段。不重采样、不前向填充、不用其他来源或昨值补缺。保留时区、原始精度与单位；行情记录只用于本地核验，不加入仓库。
3. 逐只统计记录数、有效/缺失/无效 IOPV 数、首末时间、不同值个数、变化时点、最长不变区间、时间回退和数据缺口。缺口按来源承诺的推送规则判断，不能把无成交或休市机械地算成丢数据。
4. 对照基金计算规则和输入时点解释稳定区间及跳变；无法解释的部分明确保留为待核验。不要用期货涨跌强行要求官方 IOPV 同步变化，官方计算方法可能没有使用期货。
5. 在正常交易时段做一段实时采样，记录本机请求开始时间、接收时间、来源 tick 时间及已核验的估值时间，并确认本机时钟同步。若首次采样不能覆盖相关更新行为，再补充采样；不以历史回补代替实时观测。
6. 分别记录请求耗时和 `接收时间 - tick时间`，不得将它们标为已核验的估值时效。后续取得估值时间语义证据并做多次盘中采样后，再汇总延迟分布和门槛外样本；单次快照不能证明全天延迟表现。
7. 数据源核验通过后再接入 `data/etf_premium.py`，保留现有失效控制；做针对性的解析、时间有效性和快照一致性验证，并在部署环境抽查。五只全部满足要求且完成集成验证后，才能关闭第 19 项；部分通过只记录对应品种的进展。

历史 tick 的时间不能测出数据当时到达本系统的延迟。把历史查询的接收时间减去历史 tick 时间得到的是数据年龄，不是当时的实时传输延迟。

## 通过后再执行的业务改动

- 核验通过且确认时间语义后，新增 RQData 适配器，将交易所 tick 时间映射为 `iopv_time`；不使用本机获取时间。按已确认方案校验当日交易时段、停复牌状态与 15 分钟阈值。
- 腾讯、东方财富数值仍只用于折叠排查区。RQData 超时、异常或无效时明确记录失败并保持 `unavailable`，不得回退旧参考值参与计算。
- 有效快照才恢复实时折溢价计算、3% 提醒、页面估值时间展示及 AI 引用；完成后另行提升接口版本，不能把现有免费参考展示的版本4视为实时能力恢复。
- 第 19 项关闭前，需完成五只 ETF 的盘中时效验收、折溢价与提醒校验、一个完整交易日不回退旧值的观测，以及 RQData 断开时显示不可用的验证。优先选择包含停牌和复牌的交易日。

本节尚未实施，不能将探针的合成数据测试当作真实来源通过。

## 真实源未通过时

只有真实来源未通过，或权限、成本不合适时，再单独评估模型估算。基准净值、标的代理及汇率必须对齐基准时点，纳指期货仅作为代理；基差、现金比例、费用及汇率口径均需要验证。误差带与提醒阈值依据实际回测和观测确定，不能预先把“误差约 1%”当成已验证事实。

页面、接口和 AI 全程标注“模型估算”，使用单独字段及明确的计算依据，不填入当前 `iopv` 或将其表述为官方 IOPV。该功能单独验收，第 19 项保持未完成。
