# 问题核查与修复

本次依据桌面问题清单检查了信号决策、缠论、突破方向和数据时效性。回归使用确定性数据，实际行情复核结果仅保存在临时目录，不纳入仓库。

## 逐项处理

| 清单项 | 根因或核查结果 | 当前处理 |
| --- | --- | --- |
| 1. 风控结论与买入建议冲突 | 后处理修改了顶层 action，却保留原来的摘要和计划 action；仓位还在盈亏比否决之前生成 | 风控放入 `analysis/signal_policy.py`；全部检查完成后统一生成最终 action、摘要、仓位和计划。观望时清空入场、止损和目标价，并标记 `executable: false` |
| 2. 笔方向与中枢突破方向冲突 | 把最近完成笔直接表述成当前趋势延续；下行回踩笔本来也可能对应三类买点 | 明确标注最近完成笔及其日期。笔方向与当前中枢位置不一致时提示等待后续笔确认，不再推断“空头延续”或“多头延续” |
| 3. 已向下突破却在中枢内 | 后端使用历史笔端点突破，前端又根据价格独立选择任意包含现价的中枢 | 后端按最新K线 close 与最近中枢上下沿统一生成 `current_position`；前端直接使用该结果。历史突破另存字段用于信号识别，不能代替当前状态 |
| 4、5. 旧中枢与过期信号 | 用全历史结构及按类型拼接的数组选择“最新”；前后端还分别取最后一个和第一个 | 用最近60根K线重算，所有类型按日期排序，提供统一 `latest_signal`。过期信号单独返回、折叠展示，不进入当前信号或图表买卖点 |
| 6. 止损高于突破价 | 清单中的六个系统一信号确属做空；原代码未传递显式方向，且将空头“持仓”计入买入信号 | 新增 `direction` 和止损计算参考价；做空持仓纳入偏空评分和卖出依据。图表按每个系统自己的方向解释，页面标明模型方向与参考价。做多移动止损也可能在加仓后高于最初突破价 |
| 7. 报价失败保留旧价格 | 报价数据没有成功获取时间，失败后只修改阶段状态，名称也依赖报价成功 | 返回行情时间和成功获取时间；失败后在报价区域标记旧数据，保留原时间。首次失败从关注目录、自选和历史中补名称 |
| 8. 无时间戳、资金流原因不实 | `Quote.timestamp` 未填充或序列化；资金流空结果被直接判断为盘前/非交易日；宽度提示未区分是否已有快照 | 报价读取东方财富 `f86`（回退 `f124`），K线保留实际获取时间及最后一根日期，分析返回生成时间。资金流区分无记录与请求失败；市场宽度按 available、refreshing、last_error 显示真实状态 |
| 9. 换手率异常 | 报价换手率直接来自东方财富 `f168`，本站没有分母计算或日内重复累计；实际复核与腾讯一致 | 保留数据源原值，报价显示成交量单位和换手率来源。不按100%截断 |
| 10. 所有品种观望 | 上证评分为15来自原评分分支；大盘偏空降低评级与仓位，没有直接硬否决全部买入 | 保留原风险政策，显示决策原因。测试确认：个股条件及盈亏比合格时，即使大盘15分仍可产生轻仓买入；硬否决和盈亏比不足仍优先 |

## 缠论口径

- 分析窗口：最近60根K线。日线是60根日K，周线是60根周K。
- 价格口径：该次分析数据中的最新K线 `close`。盘中K线尚未收盘，界面明确说明。前端不拿后续实时报价重新解释旧分析。
- 中枢位置：`close > zg` 为 `up`，`close < zd` 为 `down`，包含边界的其余情况为 `inside`。
- 信号有效期：距最新K线不超过10根，且价格相对信号价的绝对偏离不超过10%。周线按周K计数，不是10个自然日。
- 三类点若在产生后出现收盘价回到或穿过对应中枢边界，也标记失效。
- 60根窗口之外的结构不参与当前分析；窗口内过期信号放入 `expired_signals`，带失效原因。
- 阈值集中在 `analysis/chanlun_daily.py` 顶部的常量中。

## 接口变化

已有路径不变，主要字段变化如下：

- `/api/analyze`：`signal.action` 与 `signal.trade_plan.action` 一致；计划新增 `executable`。不可执行的入场计划把价格字段置为 `null`；顶层 `risk_reward` 仅用于解释筛选原因。增加 `analyzed_at`、`kline_status`。
- `/api/chanlun_daily`：`signals` 只含有效信号，按日期倒序；新增 `latest_signal`、`expired_signals`、`current_price`、`as_of`、阈值及 `kline_status`。中枢增加 `current_position`，历史突破独立存储。
- `/api/quote`：增加 `timestamp`、`fetched_at`、`source`、`volume_unit` 和 `turnover_source`。缺失的上游行情时间保持未知，不用本机时间冒充。
- `/api/kline`：增加 `kline_status`。缓存命中保留原始获取时间。
- `/api/realtime_flow`：正常响应但无记录时返回 `status: "unavailable"`、`message` 和空 `flows`；请求失败仍走错误响应。
- 突破结果增加 `direction: "long" | "short" | "none"` 与 `stop_reference_price`。做空持仓状态使用 `持仓空头`；价格保留三位小数以支持ETF报价精度。

- HTTP冒烟覆盖 `/api/health`、`/api/quote`、`/api/kline`、`/api/analyze`、`/api/chanlun_daily`、`/api/realtime_flow`，使用固定数据，不依赖实时市场。
- 独立Chrome临时配置验证10项页面行为，包括报价失败、时间和名称保留、唯一结论、观望隐藏价格、统一中枢状态、过期信号、资金流与市场宽度状态、不同突破系统的方向。
- 实际复核清单中的8只ETF。报价、最终决策与缠论均成功返回；此独立检查未启动市场宽度后台缓存，因此该项按未就绪降级，没有把缺失宽度当成实时市场结果。
