# 资产分类与基金观察

## 行为与范围

品种目录、资产类型、份额配对和适用模型统一放在 `data/instruments.py`，页面通过
`GET /api/instruments` 获取。分组只负责导航，改变目录不改变分析模型。

| 资产 | 分析与展示 |
| --- | --- |
| A股股票 | 保留五模块评分、统一风控、交易计划和扫描；CAN SLIM 明确标为技术代理评分 |
| A股权益ETF、海外权益ETF、黄金ETF | 展示该品种价格趋势、区间回撤、突破模型和缠论参考；不输出个股综合分或仓位计划 |
| 短融ETF、长久期国债ETF | 展示价格趋势、区间回撤及报价成交信息；不启用股票评分、海龟突破或缠论 |
| 未细分的场内基金 | 保守展示价格参考，不推断底层资产或跟踪指数 |
| 场外联接基金 | 保留净值走势与趋势参考，增加独立申赎规则与A/C对照 |

ETF分析不会读取上证指数或A股市场宽度参与评分，也不会生成固定5%止损、默认10%目标收益或1—3个月持有期。
跟踪基准仅为资产元数据，不假装已经接入对应海外指数行情。全A股扫描仍仅扫描股票；ETF的日/周视图分别分析自身序列，未生成ETF双周期买入信号。

CAN SLIM目前的C/A为价格动量、I为资金流代理，未使用企业盈利数据。小白模式直接显示后端 `canslim.total`，不再另算七项平均值。

## 接口契约

`GET /api/instruments` 返回 `version`、`groups`、`instruments`、`profiles`、`listed_fund_prefixes`。
各品种包含 `asset_type`、`model`、`chanlun`；基金含 `share_class`、`currency` 和 `peer_code`。

`GET /api/analyze?symbol=511360` 等场内基金请求保持原有K线与报价结构，增加 `instrument`。
`signal.model` 为 `technical`、`defensive` 或 `reference`；`score`、`confidence`、`canslim` 为 `null`，
`trade_plan` 为 `{"executable": false}`，不将“不适用”转换成0分。
`signal.asset_metrics` 包含区间起止日期、样本数、价格变化和最大回撤。
这些指标使用当前加载区间的复权收盘价；周线回撤只反映周收盘，不等同日线回撤或基金总回报。

`GET /api/fund-terms?symbol=050025` 返回当前份额和已配置对照份额的 `items`。
每项包含 `instrument`、`data`、`error`；`data` 包含：

- `trading`：申购、赎回、定投、日累计限额、起购金额、确认时间。
- `fees`：分档申购费率、赎回费率、管理费、托管费、销售服务费。
- `source`、`source_url`、`fetched_at`、`effective_date`（来源未提供时为 `null`）。

该接口解析天天基金公开销售页面的表格，不执行脚本。按HTTP响应编码解码，核验页面基金代码和申赎状态；表格布局无法识别时显式报错。
未知限额/费率显示未披露，不等同无限额或免费。申购状态与限额分开保留，不因限额大于零就判断可买。
渠道折扣与原费率保留原始列示条件，不统一假设A/C的一年成本分界。
成功结果缓存5分钟，保留原获取时间。对照份额失败返回 `status: partial` 和逐项错误，全部失败返回HTTP 503；非法代码返回HTTP 400。
净值和交易规则独立请求，一方失败不会伪造另一方的结果。

`GET /api/etf-premium?symbol=513500` 仅支持已配置的五只海外ETF，返回：

- `iopv`：实时IOPV的核验状态、交易价、行情时间、估值时间及来源。未通过估值时效核验时，内层 `iopv`、`premium_pct` 为 `null`，`status` 为 `unavailable`。
- `iopv.reported_reference`：来源最近收到的参考值 `value`、来源原报折溢价 `premium_pct`、同一快照市价 `source_price`、行情时间 `price_time`、估值时间 `valuation_time`、本站获取时间 `fetched_at` 和来源。来源未提供折溢价时为 `null`，不以自行计算的比率补齐。
- `disclosed_nav`：本ETF已披露单位净值、净值日期及相对偏离；不使用联接基金净值。
- `model_estimate`：独立模型估算对象，包含 `est_nav`、`est_nav_time`、`est_premium_pct` 和各输入时点。使用实际净值日期对应的期货、USD/CNH收盘基准；没有基准或有效输入时明确不可用。详见[QDII模型估算](QDII模型估算.md)。
- `status`、`errors`：来源失败显式展示；不以旧净值冒充IOPV。

实时IOPV折溢价口径为 `(快照价格 / IOPV - 1) × 100%`，正值为溢价。解析时仍用同一快照核对来源折溢价关系；免费参考区直接展示来源返回的比率，腾讯字段77直接使用，东方财富字段f402折价率取反。
来源未提供IOPV计算时间，`iopv_time` 和 `reported_reference.valuation_time` 为 `null`。页面默认展示来源参考区，明确区分行情时间、未知的计算时间和本站获取时间；来源最近收到的IOPV不等于已核验的当前估值。
报价时间必须与数据日期一致；价格、参考值非正数或非有限数报错，缺失参考值返回 `null`。
成功快照缓存15秒，每次返回重新判断时效。只有报价与估值时间均非未来、距当前不超过120秒且数据完整时才允许实时提醒；前端也按 `fresh_until` 取消到期提醒。参考对象的 `quote_fresh_until` 仅用于标记旧报价，不能证明IOPV时效。
提醒阈值初始为3%，仅对有效实时IOPV开放调整。免费来源参考区不触发提醒，整个 `reported_reference` 从AI上下文移除。刷新失败时保留原参考数据和时间，并显式标注上次成功获取及失败原因。已披露净值偏离独立展示，永远不触发提醒。
该免费展示和模型估算无需RQData账号或SDK；`/api/health` 的 `premium_api_version: 5` 标识新增模型估算，模型仅作5%信息提示并在AI中明确标注，第19项仍未完成。

## 数据来源核验

2026-11-17核验以下公开来源；第三方页面/字段并非稳定合同，解析失败应直接暴露：

- [基金代码表](https://fund.eastmoney.com/js/fundcode_search.js)：核对人民币A/C名称和代码。
- [费率表样例](https://fundf10.eastmoney.com/jjfl_050025.html)：申赎状态、限额、分档费用。
- [ETF净值样例](https://fund.eastmoney.com/pingzhongdata/513500.js)：沿用已有净值解析，校验基金代码。
- [AKShare公开适配实现](https://github.com/akfamily/akshare/blob/master/akshare/fund/fund_etf_em.py)：核对东方财富 `f441` 为IOPV、`f402` 为折价率、`f124` 为行情时间、`f297` 为日期；随后直接读取东方财富公开响应核验数值关系。
- [ETF参考值来源](https://push2delay.eastmoney.com/api/qt/ulist.np/get)：使用参数化 `secids`、`fields`、`fltt=2` 请求同一快照。

没有调用账户、下单或外部消息接口。没有保存抓取的行情快照到仓库。
